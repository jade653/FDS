# 검수 관점: 실제 실행 환경에서의 장애

이 문서는 외부 검수자(사람 또는 다른 모델)에게 주는 **관점과 결과 형식**이다. 시점과 무관하다.
검수 대상 커밋과 배경 사실은 `docs/review-brief.md`에 있다.

## 왜 이 관점인가

감시탑(offchain/packages/detector, responder, service)은 단위·E2E 테스트를 통과했지만, Sepolia에서 돌리자
로직이 아니라 **실행 환경이 가정과 달라서** 생긴 장애가 여러 건 나왔다. 테스트는 가짜 RPC(FakeRpc, FakeChain)와
로컬 Anvil에서 돌기 때문에 이런 차이를 보지 못했다. 같은 종류의 문제가 더 있는지 찾는 것이 목적이다.

## 실행 환경과 요구

- Sepolia: 무료 공개 RPC(publicnode), 블록 약 12초, 과거 상태는 최근 블록만 보관, 공개 멤풀의 대기 거래 초당 수십 건,
  WebSocket이 몇 분 만에 끊기기도 함
- 다음 대상: 자체 EVM 체인, 블록 약 2초, 거래는 적음, RPC 위치 미정
- 요구: 블록 하나 처리 시간 < 블록 간격. 탐지에서 동결까지 1블록 이내 (docs/design.md 7.4)
- 구체 수치(측정값, 감시 지갑 수 등)는 `docs/review-brief.md`를 따른다

## 이 관점으로 본다

1. **외부 의존 가정**: RPC가 느리거나, 오류를 내거나, 과거 상태가 없거나, 연결이 끊기거나, 요청 제한에 걸리면
   어떻게 되는가. 재시도·타임아웃·대체 경로가 있는가.
2. **끝없이 쌓이는 것**: 줄(큐), 동시 요청, 메모리, 재시도, 알림이 상한 없이 늘어나는 곳. 넘칠 때 무엇을 버리고
   그 결과 무엇을 놓치는가.
3. **시점과 순서**: "그 블록 시점의 값"이어야 하는데 "지금 최신 값"을 읽는 곳. 처리 지연이나 재처리(재시작, 재조직,
   따라잡기) 때 판정이 달라지는 곳. 경합 조건.
4. **실패 처리**: 오류가 프로세스를 죽이는 곳, 조용히 멈추거나 느려지는 곳, 경보가 장애와 같은 경로에 묶여 함께
   멈추는 곳.
5. **성능 예산**: 블록 하나당 RPC 요청 수와 왕복 시간. 감시 지갑 수, 블록 크기, 블록 간격(12초 / 2초)에 따라
   어떻게 늘어나는가. 밀렸을 때 따라잡을 수 있는가.
6. **테스트의 빈틈**: 각 가짜 객체(FakeRpc, FakeChain, FakeChain of responder 등)와 Anvil이 실제 체인과 다르게
   가정하는 것. 그 차이 때문에 통과하는 테스트.

자금과 권한에 직결되는 경로(Responder 서명, 동결 판정, 승인 링크)는 위 관점에서 더 엄격하게 본다.

## 결과 형식

발견마다:

- 심각도 (높음 / 중간 / 낮음)와 그 이유
- 파일:줄
- 실제로 어떻게 실패하는가: 구체적인 상황과 그때 일어나는 일
- 확인 여부: **확인함**(재현·측정함) 또는 **추측**. 확인했다면 방법과 결과
- 고치는 방향 (코드 수정은 하지 않는다)
- 이 문제를 잡을 테스트

가능한 것은 로컬 Anvil에서 재현하거나 Sepolia에서 측정해 확인한다. Sepolia에 거래를 보내거나 배포하지 않는다
(읽기만). 스타일, 이름, 주석 지적은 빼고, 같은 원인의 발견은 하나로 묶는다.

`docs/review-brief.md`에 적힌 이미 고친 문제는 다시 지적하지 말고, **같은 종류의 문제가 다른 곳에 있는지**를
찾는다. 브리핑의 추측과 기존 조치는 이전 작업자의 판단이므로 믿지 말고 검증한다.
